## Ownership and readability rules

* Assign each source function, nested helper, and split inline block exactly one implementation owner
* Keep repeated invocations visible under their actual callers, with actual inputs, returned outcomes, and a link to the owner; do not repeat the helper's branch logic or internal calls
* Distinguish an interface summary from implementation coverage: an output schema or one-sentence side-effect contract can appear at a call boundary without reproducing the implementation
* Keep small private helpers with their owning operation unless their reuse or complexity warrants another chart
* Own nested functions with their lexical parent unless explicitly extracted below; a callback invocation must still show its real dispatcher and execution boundary
* For a split function, label the child chart as a continuation of that same function, not a new call; show incoming local state and the precise point where control resumes
* Target 12-25 documented call rows and 120-200 trace-body lines per new chart, excluding template CSS and JavaScript; split before exceeding 30 calls or 200 trace-body lines
* Avoid padding small charts to meet a minimum; keep actual call depth accurate rather than flattening it to meet a visual target
* Use the existing fully expanded template, optional folding, relative source links, and stable entry anchors; folding is not a substitute for sensible boundaries
* Give each chart its own scenario, real caller or unused-API label, input/state contract, outputs, early exits, consequential alternatives, write locations, and failure boundary
* Keep shared input types understandable in isolation without copying another chart's implementation; define terms such as normalized key, retained source scan, and partial-progress result where used
* Treat template duplication as standalone-page presentation, not duplicated coverage of the scripts being traced

The ownership tables below describe the generated layout, with the size-driven refinements listed next. Every definition has one canonical implementation; callees in other charts are linked boundaries, not additional ownership. Types and configuration constants appear as interface schemas rather than separate execution trees. The machine-readable ledger is the precise source-range inventory.

* [Directory identity](./directory-identity.html) owns the local directory-stat, ancestor-verification and emptiness helpers plus the Windows volume helper; [directory cleanup](./directory-cleanup.html) retains orchestration and its warning callback

* [Kit profiling](./kit-profiling.html) owns XML loading and its local walk/record helpers; [kit comparison](./find-similar-kits.html) retains the CLI, candidate matching and display-label helper

These splits keep every new chart within 30 call rows and 200 trace-body lines without hiding code by default. Function ranges exclude separately owned nested definitions. The extraction entry, song-loop continuation and apply/output continuation have complete, disjoint statement-aligned ranges.
