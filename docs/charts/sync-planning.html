Sync planning and change detection

Scan source and destination, classify each source file, then schedule removal of destination-only files

  1. syncing.py compute_sync(source: Path, dest: Path, *, manifest: FilesDict | None = None, source_is_sd: bool = True, file_filter: FileFilter = "both") tuple[SyncPlan, ScanResult]

    Called from SD-to-local orchestration; direction changes manifest field mapping, not the source-wins copy policy

    1. syncing.pySyncPlan()
      ResultEmpty copy/removal lists and files_unchanged=0
    2. scanning.pyscan_tree(source, label="source", file_filter=file_filter)ScanResult

      Collect filtered source metadata; expand filesystem scanning

      Returnsrc_scan indexed by normalized relative key
    3. scanning.pyscan_tree(dest, label="destination", file_filter=file_filter)ScanResult

      Complete source scanning before starting destination scanning; same scanner flow

      Returndst_scan indexed by normalized relative key
    4. For each (key, src_entry) in src_scan.files, in scan insertion order
      1. StatePrint comparison progress; src_path=source/src_entry.rel_path and dst_path=dest/src_entry.rel_path
      2. If key is absent from dst_scan.files
        1. StateAppend (src_path, dst_path) to files_to_copy; continue with the next source file
      3. Otherwise, if manifest is not None and contains key
        1. Inputmanifest_entry references the caller's existing record; refreshes below mutate that record
        2. StateIf source_is_sd: SD=source and local=destination; otherwise SD=destination and local=source
        3. If SD sizes match, evaluate the second operand of the metadata-change check
          1. syncing.py_mtime_matches(sd_entry.mtime, manifest_entry["sd_mtime"])bool
            Returnabs(mtime_a - mtime_b) <= 2.0
        4. If SD size differs or SD mtime is outside the tolerance
          1. If a cached hash exists
            1. deluge_sdk.pyhash_file(sd_path)str

              Read in 64 KiB chunks and compute SHA256

              ReturnCurrent SD content digest
            2. If digest differs from the cached hash
              1. StateSchedule source-to-destination copy and continue with the next source file
            3. Otherwise, SD content matches the cached hash
              1. StateRefresh sd_size and sd_mtime in manifest_entry; continue to the local check below
          2. Otherwise, no cached hash exists
            1. StateConservatively schedule source-to-destination copy and continue with the next source file
        5. Statehas_local_changed compares local size and exact local mtime against the manifest
        6. If local mtime > 0 and local metadata has not changed
          1. StateIncrement files_unchanged without hashing
        7. Otherwise, verify the local file, including when mtime is zero
          1. If a cached hash exists
            1. deluge_sdk.pyhash_file(local_path)str
              ReturnCurrent local SHA256 digest
            2. If local digest matches the cached hash
              1. StateRefresh local_size and local_mtime in manifest_entry; increment files_unchanged
            3. Otherwise, local content differs
              1. StateSchedule source-to-destination copy
          2. Otherwise, no cached hash exists
            1. deluge_sdk.pyhash_file(local_path)str
              ReturnLocal SHA256 digest to seed the existing record
            2. StateStore the local hash, size, and mtime in manifest_entry; conservatively schedule a copy anyway
      4. Otherwise, no manifest record exists for this file
        1. If source and destination sizes differ
          1. StateSchedule source-to-destination copy without checking mtime
        2. Otherwise, compare modification times
          1. syncing.py_mtime_matches(src_entry.mtime, dst_entry.mtime)bool
            ReturnTrue for an absolute difference of at most 2 seconds
          2. StateTrue: increment files_unchanged; False: schedule a copy
    5. For each (key, dst_entry) in dst_scan.files
      1. If key is absent from src_scan.files
        1. StateAppend dest/dst_entry.rel_path to files_to_delete
    6. OutputPrint final comparison count
    Return(plan, src_scan); no copy, removal, or manifest persistence occurs here
    ExceptionHashing errors propagate; no SyncError conversion is performed during planning

Existing callers: sync_from_sd.py uses source_is_sd=True; sync_to_sd.py uses False; sync_samples_to_cloud.py uses manifest=None and file_filter="wav"

No-manifest comparison uses size and mtime, not hashes; unchanged metadata is not a proof of identical content
